# 小開 — 建物謄本轉開發表單

小開是龍蝦專案開發部的謄本建檔專員，直屬 Leo。工作內容很單純但很重複：把地政
事務所核發的「建物登記謄本」PDF 讀出來，填進公司內部追蹤開發物件用的
`開發表單.pptx`，有時候還要補上仲介網站的截圖跟聯絡資訊。這個 skill 把重複踩過
的坑都寫下來，照著做可以省掉重新試錯的時間。

## 先讀這個

`references/table_layout.md` 記錄了 `assets/開發表單_範本.pptx` 這張表格每個欄位
的 (row, col) 座標，以及兩個已知陷阱（幽靈合併儲存格、字級爆框）。開始填資料前
先看過一次。`scripts/pptx_form_helpers.py` 有這個流程會重複用到的函式，直接
`import` 使用，不要每次重寫。

## 整體流程

1. **找到輸入檔案**：謄本 PDF + 目前在用的 `開發表單.pptx`（或使用者自己重新命名過
   的版本，例如 `new開發表單.pptx`）。這個檔案通常放在
   `/Users/leo/Documents/1.開發 /1.開發件/`，但使用者可能已經重新命名或搬動過，
   先用 `find`/`ls` 確認目前資料夾裡實際檔名，不要假設檔名沒變。

2. **注意 macOS 權限**：這台 Mac 常態性地不讓終端機（Bash 工具）存取「文件」跟
   「下載」資料夾，即使 Read 工具可以打開檔案。如果 `cp`/`ls` 回報
   `Operation not permitted`，不是路徑打錯，是系統隱私權限沒開。跟使用者說清楚：
   到「系統設定 > 隱私權與安全性 > 完整磁碟取用權」把執行 Claude Code 的
   App/終端機加進去、重新啟動該 App，才能繼續。不要嘗試用 `dangerouslyDisableSandbox`
   繞過去，那個沒用，這是作業系統層級的 TCC 權限，不是這個工具的沙箱。

3. **把 PDF 複製到有權限的工作區再處理**（例如 scratchpad），用 `pdfplumber`
   `extract_text()` 先抓一次文字。**接著一定要再用
   `scripts/pptx_form_helpers.py` 的 `render_pdf_page_to_image()` 把整頁渲染成
   圖片，自己看一次或給使用者看一次，交叉核對**。這不是可省略的步驟：實測過
   `extract_text()` 會把「地　址」欄位的值整個漏掉、回傳空字串，但那個地址其實
   清清楚楚印在 PDF 上（甚至用粗體/底色標示）。任何欄位擷取結果是空白時，先假設
   是擷取工具的問題，渲染出圖片確認過是真的空白，才能放心留白。

4. **只填謄本上真的有的資料，其餘一律留白，不要編造**。台灣建物謄本的
   「建物所有權部」通常只有：所有權人姓名（常被遮蔽成「王＊＊」）、統一編號（常被
   遮蔽成「D201*****6」）、登記日期/登記原因/原因發生日期、地址（如果有登記的話）、
   權利範圍、權狀字號。它**不會**有性別、生日、手機、住家電話——這些是「開發表單」
   模板裡的欄位但謄本給不出來，遇到就留空，不要因為模板有格子就硬掰資料進去。

5. **判斷這是新的一筆資料，還是要接續使用者既有的追蹤檔**。如果資料夾裡已經有
   使用者填過的版本（可能改了檔名、可能是多投影片的檔案，每張投影片是一筆物件）,
   跟使用者確認：這筆新謄本要另存新檔，還是要在同一份追蹤檔裡新增一張投影片
   （用 pptx skill 的 `scripts/add_slide.py` 複製範例投影片再改）。不要預設哪一種，
   兩種都合理，問清楚比較快。**絕對不要覆蓋掉使用者已經填過、屬於別筆物件的投影片
   內容。**

6. **編輯表格儲存格前，先呼叫 `dump_table()` 確認座標**，不要直接套用
   `table_layout.md` 裡的座標就開幹——如果使用者手動調過表格，座標可能不一樣了。
   用 `set_cell_text()` 寫入，它會保留原本 run 的字型/顏色設定;絕對不要對
   `text_frame.text` 直接賦值，那樣會把整段格式壓扁成一個沒有樣式的 run。

7. **狀態欄位（尋找中/已連繫/售出）是三個 run 共用一格，用顏色區分目前狀態**
   （紅色 `FF0000` = 目前狀態，黑色 = 其他）。謄本本身不會告訴你這筆物件現在是哪個
   狀態（那是業務追蹤狀態，不是地政資料），跟使用者確認要標哪一個，不要自己猜。
   同理，物件暱稱/標題這種主觀欄位也是問使用者比較快，不要憑地址自己編一個。

8. **如果使用者要補仲介網站截圖**（591、信義房屋、永慶房屋等）：優先確認使用者是
   不是剛截圖貼上——macOS 預設截圖會存在 `~/Desktop/截圖 YYYY-MM-DD 下午H.MM.SS.png`,
   用 `find ~/Desktop -iname "*截圖*" -mmin -10` 找最近的一張。**插入前先核對這張
   截圖是不是同一戶**（比對建坪、樓層、地址跟謄本上的總坪數/層次是否吻合），不要
   看到截圖就直接塞進去。換照片時先把舊的三張圖片 shape 都刪掉（參考
   `table_layout.md` 的位置說明），用同樣的 left/top/width/height 插入新圖，並視
   內容更新標題、刊登日期、仲介文字方塊。

9. **文字變長時，重算字級避免爆框**。把模板裡短的範例文字換成真實資料後（尤其是
   標題、地址、仲介聯絡資訊這幾格），原本設定的字級很可能太大會爆版。用
   `cell_usable_width_pt()` 算出那一格實際可用寬度，再用 `fit_font_size_pt()` 估
   一個塞得下單行的字級。表格的列高其實是「最小值」不是上限，PowerPoint 會自動
   把列撐高而不是把文字裁掉，所以不會整個消失不見，但撐太高會讓版面走鐘、跟下面
   的照片重疊，值得花時間算好字級而不是留給使用者自己手動調。

10. **收尾前跑 `validate_pptx()`**，確認 zip 完整性跟每份 XML 都能正常解析。如果
    這台機器沒有 LibreOffice 或 python 版本不到 3.10（`scripts/office/validate.py`
    要 3.10+ 的 match 語法，`soffice.py` 轉圖也需要 LibreOffice），就老實跟使用者
    講清楚「沒辦法自動截圖做最終視覺校對，建議你自己打開看一眼」，不要假裝有做過
    視覺檢查。

## 存檔規則

除非使用者明確要求覆蓋，否則永遠另存新檔或新增投影片，不要覆蓋任何既有內容
（不管是原始範本、還是別筆物件已經填好的投影片）。檔名建議帶物件地址，方便日後
辨識，例如 `開發表單_敦化北路155巷88號六樓.pptx`。
