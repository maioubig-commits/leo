# 開發表單.pptx 表格欄位對照表

這是 `assets/開發表單_範本.pptx` 第一張投影片裡，那張大表格（shape name「表格 3」）的
可見儲存格座標對照。用 `scripts/pptx_form_helpers.py` 的 `dump_table()` 在任何一份
同款複本上重新產生一次，確認欄位沒有被使用者手動搬動過，再照著填。

| (row, col) | 欄位 | 備註 |
|---|---|---|
| (0, 0) | 物件標題/暱稱 | gridSpan=3，原範例「雙敦三房美妝」 |
| (0, 3) | 狀態：尋找中 / 已連繫 / 售出 | 一整串文字含 3 個選項 run，目前選中的那個會被上紅色（`FF0000`），其餘黑色；換成別的狀態時要動 run 層級的字色，不是整格文字 |
| (2, 0) | 建物地址 | gridSpan=10，整列寬，字級預設 32pt，地址變長時容易爆寬要重算字級 |
| (3, 0) | 登記日期（民國年） | gridSpan=2 |
| (3, 2) | 登記原因 | gridSpan=4，格式「登記原因 : 買賣」 |
| (3, 6) | 「戶籍地址」標籤 | gridSpan=2，固定文字，通常不用改 |
| (3, 8) | 戶籍地址內容 | gridSpan=2，謄本上「地　址」欄的值;常常被 pdfplumber 漏掉，務必用 `render_pdf_page_to_image()` 渲染出來目視確認 |
| (4, 0)/(4,1)/(4,4)/(4,5)/(4,7)/(4,9) | 統一編號/姓名/性別/生日/手機/住家電話 表頭 | 固定標籤列，不用改 |
| (5, 0) | 屋主統一編號 | 謄本上通常是遮蔽版，如 `D201*****6`，照抄不要試圖還原 |
| (5, 1) | 屋主姓名 | gridSpan=3，謄本上通常也是遮蔽版，如 `王＊＊` |
| (5, 4)/(5,5)/(5,7)/(5,9) | 性別/生日/手機/住家電話內容 | 謄本（地籍謄本）本身不含這些，留空，不要編造 |

## 已知的「幽靈儲存格」陷阱

這份範本裡有幾個 `hMerge="1"` 的儲存格，理論上不會被渲染，卻殘留著舊文字（例如
(0,1) 殘留了另一份「尋找中/已連繫/售出」文字，(5,3) 殘留了「女」）。這些是先前
手動調欄寬時留下的死格，**不會顯示**，不用理它們，也絕對不要把資料寫進去以為
是在填(0,3)或(5,4)。一律用 `dump_table()` 印出的座標為準。

## 照片與仲介資訊（選填）

原範例左下方有 3 張圖片（shape name「圖片 7」「圖片 10」「圖片 11」）和一個文字方塊
（shape name「文字方塊 5」，兩段：`刊登：YYYY\MM\DD` / `仲介：xxx`）。「圖片 7」是
實際顯示在版面上的物件截圖（位置約 left=253279 top=1237685 width=5354829
height=2981172 EMU），另外兩張在畫布外（x 超過投影片寬度），是備用/裁切前的原圖，
通常不用管。換照片時先把三張舊圖都刪掉，再用同樣的 left/top/width/height 插入新圖，
避免留著跟這筆新物件無關的舊照片。
